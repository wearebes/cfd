# Capillary wave official data

Archived local data for Basilisk's official `test/capwave.c` benchmark.

## Contents

- `raw/official_vof/`: official VOF run to source resolution `N = 128`.
- `raw/official_clsvof/`: official CLSVOF run to source resolution `N = 128`.
- `raw/extended_vof/`: same setup extended to source resolution `N = 512`.
- `raw/extended_clsvof/`: same setup extended to source resolution `N = 512`.
- `figures/author_style/`: figures generated by `tools/capwave/`.
- `sources/`: `capwave.c`, `capwave-n512.c`, and `prosperetti.h` snapshots.

## Data columns

Each `wave-*` file has two columns:

1. `tau = omega0 * t`
2. reconstructed interface amplitude

Each `log` has two columns:

1. `N/L0`, the number of grid points per wavelength
2. relative RMS error against `sources/prosperetti.h`

For this benchmark `L0 = 2`, so the official `N = 16, 32, 64, 128` runs appear
in `log` as `8, 16, 32, 64`. There is no `wave-8`; amplitude files are named by
the source resolution `N`.

## Plotting

Run:

```bash
tools/capwave/plot_capwave.sh
```

The plot metrics, axes, ranges, log scales, reference curves, and line/point
semantics follow Basilisk's official gnuplot blocks. Only colors and line
styles are changed.

The additional `capwave_rms_convergence_extended.svg` keeps the same RMS metric
and plotting semantics but converts the `log` abscissa from `N/L0` back to
source resolution `N`, so the extended `N = 256, 512` runs appear at 256 and
512 on the x axis.
